# 采集与计量边界

## 依赖与降级

- 离线分析：Python 3.10+ 标准库，无网络、第三方 Python 包或外部字体。
- 在线采集：可选 ego-browser CLI 与其浏览器。运行 `scripts/capture.py --doctor` 探测；必须先遵循宿主现有的 ego-browser 使用文档。工具缺失时接受用户导出的 Chrome Performance JSON。
- HTML 预览使用任意本地 HTTP 服务；文件本身无外部依赖，可离线打开。

## 采集要求

用户授权 URL 后，在同一任务空间打开站点。页面导航超时但已提交时检查当前状态，不创建额外空间绕过问题。默认采集 25 秒，可在 5–60 秒内调整；等待时长是采样窗口，不是页面加载耗时。保持前台，无网页交互。保留现有缓存；限速、窗口和环境差异应随结果说明。

所有 tracing 操作在同一次 ego-browser nodejs 调用内。结束后等待 tracingComplete；超时不把部分录制当完整结果。采集器只保存 tracing 数据及 Performance API 快照，不保存 CDP 原始请求/响应头。但 trace 本身仍可能含 URL 参数、脚本片段及站点数据，默认本地分析，不上传、公开或提交版本库。

## 解释结果

Performance API 的资源列表与 trace 中完成的请求列表覆盖不同，数量不必相同。缓存、跨域计时限制与精度会产生零耗时或零传输大小，不能据此说资源为空。

LCP 是候选绘制时间，不是停止录制的时刻。轮播、候选变化、节点替换都可能影响最终 LCP。图片已可见却出现晚 LCP 时，先检查候选节点与画面，不自动认定 19 秒持续阻塞。

四段耗时只在导航首字节 ≤ 资源开始 ≤ 资源完成 ≤ LCP 时展示；Early Hints 可能使 responseStart 早于最终响应头，不把资源开始前的整段都归咎于客户端。不同 Chrome trace 格式可能缺少所需事件；此时明确报错，不伪造支持。

嵌套区间按最内层可识别工作类型统计，脚本来源来自最内层包围调用。关联到脚本的样式/布局时间不是该文件纯 JavaScript 自耗时；lineNumber 是录制里的位置，压缩代码没有源码映射时不恢复函数名。
