# subaru-brainstorm

面向问题探索与创意发展的 Agent Skill。帮助你澄清问题、探索不同方向、深入发展选中的想法，并在需要时整理为候选方案或验证实验。

[English](README.en.md)

## 适合什么时候使用

- **问题还不清楚**：已有一个愿望或困扰，希望找到更值得讨论的问题。
- **需要打开思路**：探索产品用途、内容选题、服务设计或团队协作方式。
- **点子开始重复**：现有想法太相似，希望换角度、拆开假设或借鉴其他领域。
- **已有想法需要发展**：深入某个方向、组合几个点子，或保留相互冲突的路线。
- **准备作出选择**：依据目标比较候选方案，明确取舍和需要验证的条件。
- **需要暂停后继续**：保存当前讨论的关键内容，下次从选中的分支接着展开。

如果你已明确要实现或修复什么，可以直接让 Agent 执行。需要探索选项、重新定义问题或比较路线时，再使用本 skill。

## 快速开始

安装并让宿主 Agent 加载该 skill 后，用自然语言说明你的问题即可。在支持 `$skill-name` 的宿主中，可以这样调用：

> 用 $subaru-brainstorm 探索一个团队知识库还能有哪些用途。面向远程团队，先给 20 个不同机制的想法，暂时不要评价。

也可以从模糊需求开始，无需先准备完整需求文档：

> 用 $subaru-brainstorm 想想怎样让团队讨论更容易接续。我还没确定是工具、流程还是活动，先给几个不同入口。

为了让结果更贴合需求，可以补充：**希望改变什么、面向谁、已有材料或限制、想要多少内容、是否允许评价**。这些信息可以在讨论中逐步补充，不必一次填齐。

## 怎样推进讨论

你可以随时改变方向、补充自己的点子或结束讨论，无需遵循固定步骤。

| 你想做什么 | 可以这样说 |
|---|---|
| 继续发散 | “再给 10 个方向，先别评价。” |
| 突破重复 | “这些都依赖用户主动参与，换一个基本假设。” |
| 深入一个想法 | “沿第三条继续，推演一次具体的使用过程。” |
| 发展自己的点子 | “我想到可以让新人接续老成员的问题，帮我展开。” |
| 组合方向 | “合并第二和第五条，说明组合后的机制。” |
| 保留分歧 | “这两条先分开发展，暂时不选。” |
| 整理而不筛选 | “按实现机制归类，保留所有方向，继续先别评价。” |
| 比较并推荐 | “按我们的目标比较这三条，说明各自依赖什么条件，再给建议。” |
| 形成下一步 | “把选中的方向整理为一个小规模验证实验。” |

默认探索时会延迟评价，给不同路线留下发展空间。**整理或归类不会自动变成排名与淘汰**；希望比较、推荐或确定方案时，直接说明即可。

你引用过的想法会保留稳定编号，便于后续讨论。重新排序或合并时仍会保留原有指向与来源；暂存的路线也可以重新展开。

## 可以得到什么

交付形式取决于你的用途，不要求每次输出完整报告：

- **想法清单**：用于打开思路，可以指定数量、形式和评价时机。
- **探索地图**：梳理当前问题、不同路线、路线之间的关联和待展开区域。
- **候选方案**：说明适用情境、核心机制、依赖条件和仍未验证的假设；需要时提供比较与建议。
- **实验卡**：把一个方向转化为具体尝试，明确要了解的问题、尝试方式和观察内容。
- **续谈摘要**：保留目标、限制、当前分支、已作出的选择、未决事项和下一次切入点。

例如，从探索走向验证时可以说：

> 将“异步接续讨论”整理成一个候选方案，说明谁在什么情境下使用、一次具体交互和关键假设，再设计一个三人就能尝试的小实验。

## 暂停、保存与继续

暂停时可以说：

> 给我一份可用于下次继续的摘要，保留当前目标、先别评价的约定、我选中的方向、其他待展开路线，以及下一步。

下次将摘要贴进对话，并说明从哪里继续：

> 用 $subaru-brainstorm 根据下面的摘要继续。目标不变，先展开上次选中的分支，仍然先别评价。

如果宿主支持文件读写，也可以要求将摘要保存到项目中的指定文件，并在下次提供该文件。没有文件工具时，可以复制对话中的摘要。跨会话接续依赖你提供的摘要或文件，不保证宿主具有永久记忆。

## 使用边界

核心流程只需要宿主的对话能力，无需第三方运行依赖。资料搜索、文件保存、分支图以及文档或演示产物，取决于宿主实际可用的工具；相关能力缺失时会说明，并提供可行的对话交付方式。

生成的想法、场景推演和建议仍需结合现实验证。候选方案不代表已经实施，实验设计不代表已经获得真实观察；需要事实依据时，可以明确要求调研或核实。
