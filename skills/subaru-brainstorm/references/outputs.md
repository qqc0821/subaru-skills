# 整理与交付

按用户用途选择形式，不固定输出整套模板。用户只要点子时，直接交付点子。

## 探索地图

适用：想看讨论到了哪里，或要求整理但仍延迟评价。

保留当前问题、几条路线及关联、未展开区域、暂存异议。
可以按机制归类，保留原编号；相似不等于无用，不以分类暗示排名。
如果画图能力缺失，使用短段落、列表或 Markdown 表格即可。

## 候选方案

适用：用户要求方案、比较或推荐。

每个需要讨论的候选包含：
- 谁在什么情境使用，期望发生什么变化。
- 核心机制与一次具体交互。
- 依赖条件、事实依据与仍未验证的假设。
- 可以怎样继续探索或尝试。

用户要求推荐时，依据他的目标说明条件式取舍；缺少依据时说明选择是假设。
区分有依据的当前行动与取决于未明偏好的后续选择，不默认用户愿意维持关系、退出或尝试。
用户仍纠结时承认相互牵动的愿望，保留一个可继续的切入点；可在同轮给建议，不强制先问问题。
若用户要求直接结论或话术，按已知条件交付；后来补充关切时可重新探索，不把上一轮建议当成用户决定。
将相处距离、机会处理等不同维度分别呈现，不伪装成互斥路线。第三方承诺须与本人意愿区分。
不用看似精确的创新分数替代证据。不把模拟人物反应写成用户验证结论。
要求最终一版方案时可以组合几个方向，记录来源与暂存问题，不继续给无穷选项。

## 实验卡

适用：用户准备验证一个方向。

```text
想法：I07，异步接续匿名异议。
要了解：参与者是否会接续不属于自己的问题？
尝试：用一次三人讨论人工模拟，邀请每人接续一条。
观察：是否接续、在哪里停住、希望补什么信息。
可能学到：无人接续也可能是问题不清楚，需要追问原因。
之后：根据观察修改问题表达或展开另一分支。
```

实验应尽量小、可逆；访谈、外部消息、发布与付费操作遵循宿主授权。
提出实验不等于已经执行；没有真实观察则保持未知。

## 结束或暂停

用户说结束就停止发散。需要续谈时提供 [快照](session.md)，也可只给下一次切入点。
交付说明保持简短：产出了什么、哪些仍是假设、下一步从哪里继续。
