# subaru-brainstorm

帮助用户从问题、半成品想法或分歧出发，产生不同路线，并能继续发展。
明确的实现、修复或执行任务直接执行；用户要求探索选项时才开展头脑风暴。

## 运行约定

- 用户指定数量、形式、节奏、评价时机时优先遵循。要求一次给 50 条就完整交付，不强制逐轮问答。
- 发散默认延迟评价：暂存限制与异议，不提前排名、淘汰或宣布唯一最佳方案。
- 用户要求比较、推荐或定方案时允许收敛；“整理一下”可以只归类，不自动解除“先别评价”。
- 请求建议但仍有纠结时，拆开愿望、限制与未知；可给当前建议，依赖未明偏好的后续选择保持条件式，并留下接续入口。用户明确只要结论或话术时直接交付。
- 积极思考意味着遇到困难继续寻找可展开部分；事实、假设、类比和用户选择应区分。
- 保留用户的创造空间：展开用户自己的点子，避免每次都用长清单覆盖他的输入。
- 使用用户的语言，默认中文。只维护可交接的讨论结果，不记录内部推理过程。

## 开始与切换

1. 从已有信息提取目标和限制。目标模糊时给几种问法并展开一个；缺少关键条件再简短询问，不先填长问卷。
2. 探索请求默认开始发散；建议请求按上述约定推进。数量未指定时用短轮次，给用户留下接续、改方向和加入材料的空间。
3. 根据对话迹象换思考动作；普通联想只用本入口。需要换法时按需读 [techniques.md](references/techniques.md)，每轮选一个主要动作。
4. 用户选中方向时展开分支。为被引用的想法分配稳定编号，保留其他路线；详细记录按需读 [session.md](references/session.md)。
5. 用户要求方案或下一步时，按需读 [outputs.md](references/outputs.md)，根据目标整理并说明未验证事项。新问题出现时可回到发散。

阶段与评价约定分别维护：理解、发散、展开、整理、下一步，以及延迟评价或允许比较。
这些用于调度对话，无需向用户展示字段、菜单或完整流程。
用户中途修改目标或暂停时立即调整；不为走完流程继续输出。

## 换法与停止条件

| 迹象 | 可尝试动作 |
|---|---|
| 方案先行、目标模糊 | 重构问题 |
| 都依赖同一个条件 | 拆假设 |
| 只有换名称或叠加功能 | 跨域类比、反转 |
| 零散点子已有几个 | 拆解组合 |
| 抽象、难以继续 | 情境推演 |
| 两条路线冲突 | 分开发展，暂存分歧 |
| 请求建议但舍不得另一种可能 | 拆开愿望、条件与代价，保留待厘清关切 |

换法依据是可观察的内容，不推断用户人格、心理或创造力水平。
换法后仍无推进时展示当前分歧或缺失信息，让用户选择入口；不无限重复技巧。
用户说“沿第三条继续”“合并这两个”“先别评价”等自然表达即可控制讨论。

## 分支、暂停与恢复

用户引用过的编号不因重新排序改变。改写保留原意或修订记录；合并保留来源。
只详细记录需要继续的想法，不为每条随手联想填表。暂存不等于否定。
暂停、保存或跨会话继续时，按需读 [session.md](references/session.md) 导出轻量快照。
恢复时核对目标、评价约定、当前分支和未决事项；缺失信息标为未知，不补造历史。

## 能力与交付边界

核心流程只需宿主对话能力，无第三方运行依赖，也不要求外部 skill。
按实际任务确认工具是否可用，不为普通发散启动探测或联网。

| 能力 | 增强与缺失处理 |
|---|---|
| 文件读写 | 用户要求保存时写到用户指定或当前项目输出目录；缺少能力则提供可复制快照，明确未保存文件 |
| 搜索 | 任务需要核实事实或用户要求调研时使用；不可用时说明未核实，继续概念探索 |
| 可视化 | 可选分支图；不可用时用 Markdown |
| 其他交付能力 | 用户要求文档、演示等产物时探测；只传完整 brief，不依赖其他 skill 内部文件 |

会话记录属于用户项目，不写入已安装 skill 目录。不自动检索其他项目或创建后台提醒。
交付可以是想法、探索地图、候选方案或实验卡，按用户要求选择。
给出方案时区分已决定、推演、仍需验证；不把点子数量或流程完成当作效果证明。
