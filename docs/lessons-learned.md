# Lessons Learned

项目级经验沉淀。每次踩坑后追加一条，格式：症状 / 根因 / 修复 / 防回归。
Harness 能自动拦住的，尽量转成对应 check；拦住不了的人工智慧写在这里。

## L-01 【出图】过度约束 prompt 会杀死多样性
- **症状：** 加上颜色比例、构图位置、角色姿势后，10 页只有 1 个雷同角色。
- **根因：** few-shot 与细节约束越细，模型探索空间越小。
- **修复：** base style 只描述情绪与世界观（≤5 行），per-slide 只给内容与感受。
- **防回归：** 文档规则 + H6 eval 看 `font/tone` 多样性（后续可加）。

## L-02 【一致性】反向约束与"描述情绪"原则冲突
- **症状：** 一处要求"始终写 NOT Snoopy"，另两处明确禁止写 NOT。
- **根因：** 不同时期的经验写进了不同文件，没有跨文件一致性检查。
- **修复：** 统一为"不写 NOT 约束"。
- **防回归：** `tools/check_consistency.py` 的矛盾规则。

## L-03 【一致性】分辨率声明必须单一事实源
- **症状：** 同一 skill 内 `1920x1080` 与 `2048x1152` 混用。
- **根因：** 旧模板与新增模板各写各的。
- **修复：** 统一为图像生成 `2048x1152`；HTML 舞台另记 `1920x1080` 并说明换算。
- **防回归：** `single_value` 规则。

## L-04 【一致性】计数多处维护必然漂移
- **症状：** 风格数量出现 18 / 18+5 / 17（样例图）三种说法。
- **根因：** SKILL.md、gallery、样例目录各维护一份计数。
- **修复：** 以 `styles/index.json` 为唯一事实源（P0-5）。
- **防回归：** `check_style_system.py`。

## L-05 【工具】图表部件可能不在 `ppt/charts/`
- **症状：** eval 首次对真实 deck 报 chart_count=0，但文件确实有 3 个原生图表。
- **根因：** 图表实际位于 `ppt/slides/charts/chartN.xml`。
- **修复：** 检测模式改为 `charts?/chart\d+\.xml$`。
- **防回归：** H6 用真实 deck 做回归基准，而不是凭空造 fixture。

## L-06 【Harness】baseline 应"按 check 替换"而非"并集"
- **症状：** 修好一个问题后，它仍留在 baseline 里，永远不会失败。
- **根因：** `--update-baseline` 用并集写入。
- **修复：** 只替换本 check 前缀下的条目，并报告 stale。
- **防回归：** `make check` 输出 stale 提示。

## L-07 【依赖】外部 skill 硬依赖破坏可移植性
- **症状：** Path A 依赖 `$presentations`、配图依赖 `imagegen`，换宿主即失效。
- **根因：** 把"检测到则增强"写成了"必需"。
- **修复：** 能力探测 + 降级（P0-3）。
- **防回归：** `check_consistency.py` 禁止扫描。

## L-08 【仓库】生成物不应入库
- **症状：** `.codex-build/`、`output/`、`.chart-data-*/`、`__pycache__/` 全部未忽略。
- **根因：** 初始仓库没有针对构建/评测产物的 ignore 段。
- **修复：** 补齐 `.gitignore`。
- **防回归：** `check_assets.py` + PR DoD。

## L-09 【转换】复杂 CSS 效果要"快照垫底 + 文字原生"
- **症状：** 渐变/阴影/滤镜在 HTML→PPTX 中整块丢失或导致文字被栅格化。
- **根因：** PowerPoint 无法原生表达这些效果。
- **修复：** 把复杂效果预渲染为底层位图，文字仍以原生文本框绘制在最上层。
- **防回归：** Path C 文档规则 + 交付前逐页目检。

## L-10 【中文】跨机保真需要字体子集或系统回退
- **症状：** 本机正常的 CJK 字体在他人机器上变成方框。
- **根因：** 只声明了字体名，没有嵌入或回退策略。
- **修复：** ① 按实际用字子集嵌入；② 明确系统字体回退栈。
- **防回归：** `references/typography-cjk.md` 规则 + 交付前检查（P1）。

## L-11 【Skill 体积】优先优化热路径上下文，而不是盲目删资产
- **症状：** Skill 的磁盘字节主要来自样例图，但运行时冗余主要来自入口与 references 的重复、混杂和冲突。
- **根因：** 把安装包体积等同于模型上下文成本；忽略 Agent Skills 的按需加载机制。
- **修复：** 分别测量 tracked bytes、入口大小和典型引用链；保留有选型价值的冷 assets，去重热路径并拆分低内聚 reference。
- **防回归：** 继续执行 5 MiB/1 MiB 预算，并为异常标记、资源命名和能力声明一致性补充语义检查。

## L-12 【资源命名】样例文件名应直接等于 style id
- **症状：** 样例名混用了序号、中文展示名、历史别名和 style id，重命名与跨平台引用容易漂移。
- **根因：** 把面向人的展示名称混入机器稳定标识。
- **修复：** 样例统一使用 `<style-id>.webp`；中文名称仅保留在 `styles/index.json` 和 preset 的展示字段。
- **防回归：** style-system 校验应进一步验证 `sample` basename 与对应 `id` 一致。

## L-13 【Harness】语义缺陷要有最小负向 fixture
- **症状：** `make check` 能通过，但文档仍可能含损坏标记，或 style registry、preset、资产目录已悄然漂移。
- **根因：** 原有质量门只验证存在性和格式，没有验证关键语义关系。
- **修复：** 检查代码块外的 `@@`，并校验 index、preset、样例目录共同满足 `<style-id>.webp` 契约。
- **防回归：** 每条新规则至少保留一个故意失败的临时 fixture 和一个当前真实包的通过断言。

## L-14 【质量】风格样例和结构检查不等于目标场景成品质量
- **发现：** 正式汇报方向的部分 preset 尚无样例；现有 eval 主要检查对象与结构，无法证明技术述职的贡献、证据和叙事质量。
- **结论：** 收敛应先围绕具体场景建立内容证据链、可复现版式和固定条件比较，再按实际加载价值清理文档与素材。
- **后续方案：** 见 [中文技术汇报优化方案](slides-focus-proposal.md)。方案尚未实施，不把静态审查当作生成质量改善证据。

## L-15 【上下文成本】机读注册表要派生出"给人/给 Agent 的摘要"，别让 Agent 直接读注册表
- **症状：** 风格选型要求 Agent 读整个 `styles/index.json`（2 947 token），其中约 75% 是 `tier/proven/preset/sample`
  这类只有校验器需要的字段；一次 deck 的必读链因此约 7 913 token。
- **根因：** 同一份数据同时承担两个消费者的需求——校验器要完备元数据，Agent 只要"选型所需的最小集"，
  却共用同一个文件；入口也没有限制"只读选中的 1 个 preset"。
- **修复：** 用 `tools/gen_style_router.py` 从 `index.json` 生成 `styles/router.md`（主题推荐 + 按 path 分组的
  一行一风格），Agent 只读摘要；SKILL.md 明确"不要读 index.json、不要预读未选中的 preset"。
  摘要必须由源生成，并由 `make check` 比对，否则就是新增一个会漂移的事实源。
- **防回归：** `TestStyleRouter` 断言 router 与 `render(index)` 一致、覆盖全部 style id、且入口确实引用 router；
  漂移时 `make check` 直接 FAIL。
- **边界：** 该修法只降低"读什么"，不降低"读多少"——`design-principles.md` 与 `design-movements.md` 的内容重叠
  仍未处理，属后续项。

## L-16 【上下文成本】文档纪律必须变成机读断言，否则会悄悄涨回去
- **症状：** L-15 把热路径从 7 913 降到 6 103 token 后，`design-principles.md` 仍带 18 组通用色板、
  2026 趋势、全库零引用的 Viral Deck 框架，以及与 `foundation.json` 冲突的"正文 ≥24pt"；
  这些既无人引用也无人清理，因为没有任何检查关心"读起来贵不贵"。
- **根因：** 质量门只验证价格（正确性）不验证成本。`SKILL.md` 的引用索引会把冷文件写成"必读"，
  而引用索引本身没有任何机制区分"必读"与"按需"。
- **修复：** ① 瘦身两份 design 文档（2 209→537、2 016→793 token），删重复色板、趋势、零引用框架与冲突字号；
  ② 新增 `tools/check_context_budget.py`：冻结"必读路径"清单与 6 400 token 预算，限制单个必读文件大小，
  要求按需文件在入口带 `按需` 标记，并断言 router 必须小于它替代的注册表。
- **防回归：** `TestContextBudget` 用合成包验证"超预算 / 超大必读文件 / 未标记的按需文件"三类 finding 会被报出；
  真实包则断言必读路径与最差 preset 都在预算内。
- **可复用结论：** 对 Agent Skill 这类"文档即运行时"的产物，应把"上下文成本"当作与正确性并列的一等指标，
  用检查器冻结，而不是靠作者自觉。

## L-17 【质检盲区】几何校验看不见"渲染出来什么样"，像素缺陷要单独设卡
- **症状：** 用户反复看到同一批"乱样式"：数字组 `8-10` 被拆成 `8-1` / 一个孤立巨字；
  色块交界处横穿一条细带，像悬空竖线；三角箭头与连接线错位。
  现有 QA 是"逐页渲染 + 目检"，但目检以缩略图/contact sheet 进行，这类 10px 级缺陷看不出来。
- **根因：** `validate_pptx.py` 读的是 XML 属性（越界、字号、斜线、等尺寸节点），
  它拿不到"文字在框里怎么折行""三角和线是什么颜色关系"。**检查的抽象层错了**，不是阈值不够。
- **修复：** 随 skill 分发 `scripts/detect_pixel_artifacts.py`（零依赖、自带 8-bit PNG 解码），
  对渲染 PNG 做三类可测判定：① 墨块在上一组基线下 80px 内另起基线且水平重叠（`wrapped-numbers`）；
  ② 同基线字高 ≥ 邻字中位数 3 倍（`oversized-glyph`）；③ ≤40px 直带贯穿两侧各 ≥150px 的色场边界（`band-cut`）。
  判据与生成侧预防写入 `references/qa/pixel-artifacts.md`。
- **可复用结论 1：** 一个缺陷反复出现时，先问"我的检查器看的是哪一层"。XML 层过了不代表像素层过了。
- **可复用结论 2（同样重要）：** **判不了的缺陷不要假装能判。** 我最初写了 `line-occluded`
  （"连接线被卡片盖住"）：像素里"被盖住"和"正常终止在图形边缘"是同一个现象——z-order 只存在于构建脚本。
  它在真实截图上报 26 条候选，几乎全是噪声，最终**直接删除**（连同它的辅助函数），
  改由生成侧铁律 + 人眼清单覆盖；斜率/基线检测因中文字形笔画天然漂移 5–10px 同样未采用。
  宁可少报，也不要用噪声淹没真缺陷——护栏一旦被当成噪声就再也没人看。
- **边界：** 检测器只覆盖上述三类；语义错误、审美判断以及"谁盖住谁"仍属人眼清单。
  交付 receipt 必须写明跑了哪些、哪些没跑。
