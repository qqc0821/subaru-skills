# 团队知识库还能有哪些用途？

本文件为 2026-10-07 按本仓库 subaru-brainstorm 指引直接编写的一次 worked example。输入见 [prompt.md](prompt.md)。场景为原创假设，输出为实际保存的助手产物；没有外部访谈、实验观察或用户多轮对话，不作为配对评测证据。

## 目标与限制

假设一个 20 人团队的资料散落在不同文档中。探索知识库如何帮助日常协作，先保留不同机制，再演示一个方向如何变成小实验。人数与场景不是实际客户信息。

## 八个机制不同的想法

| 编号 | 想法 | 机制与具体情境 |
|---|---|---|
| I01 | 从当前任务进入资料 | 做上线检查时，直接看到对应的操作步骤；入口由任务决定。 |
| I02 | 为未解决问题留位置 | 搜索失败也能记录问题，领域负责人补答案；缺口成为工作队列。 |
| I03 | 新人解释给下一位新人 | 每个新人用自己的话重写一个答案，保留原文对照；通过转述发现理解断点。 |
| I04 | 保留决策的替代路线 | 不只记结论，还保存当时未采用的方案与条件；条件改变时可以重新讨论。 |
| I05 | 让资料暴露过期风险 | 每次使用时确认版本，过期内容进入复核队列；维护由使用触发。 |
| I06 | 问题找人，而非人找文档 | 按领域把未解决问题交给合适的人，同时把回答归档；先完成协作再补索引。 |
| I07 | 接续别人的未完成问题 | 成员认领一条未解决问题，补上下文或下一步；参与是接续，不要求直接给答案。 |
| I08 | 用真实问题做演练 | 将常见问题转成小情境，成员先作答再查资料；练习帮助发现资料难以理解之处。 |

这些方向没有排名。I01 改入口，I02 改缺口处理，I03 改学习方式，I04 改决策记忆，I05 改维护触发，I06 改人员路由，I07 改协作动作，I08 改练习方式。分类不代表淘汰任何方向。

## 演示展开：I07 → B01

这是助手为展示后续产物选择的方向，用户尚未选定产品路线。其他编号全部保留。

在一次假设交互中，成员甲留下“这份部署文档在哪个环境适用”的问题。成员乙没有直接答案，但补上自己使用的环境和遇到的差异。成员丙根据这些上下文定位到维护人。知识库保存问题、补充信息与最终来源，后续成员可以继续核对。

这里的价值假设是：成员不必一次给出完整答案，也愿意补一小段上下文。未知的是参与意愿、表达成本和任务归属；上述人物反应是推演。

## 实验卡

- **想法**：I07 / B01，异步接续未完成问题。
- **要了解**：成员是否愿意补充别人的问题？什么信息能让他们接下去？
- **尝试**：在已有协作工具里放三条经过同意、去除敏感信息的真实问题。邀请三人各选择一条，补充上下文或下一步，不要求直接回答。
- **记录**：是否接续、补充了什么、在哪里停止、是否需要追问。
- **解释边界**：没人接续，可能因为忙、问题不清楚或不知该做什么，不能直接判断没有需求。
- **之后**：询问停止原因；根据观察修改问题表达，或回到 I02 / I06 继续探索。
- **执行状态**：仅设计，未邀请参与者、未发送消息、未执行实验。
